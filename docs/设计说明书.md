## 1. 系统架构设计

```
│  pages/wrongbook.py    ── 错题本（双模式）                    │
│  pages/mnemonic.py     ── 助记助学（数字/人名/量表速查）      │
│  pages/settings.py     ── 配置管理（导入/备份/参数）           │
├────────────────────────────────────────────────────────────────────┤
│                    业务逻辑层 (Business Logic Layer)               │
│  utils/data_manager.py —— 业务层封装（1239行）                 │
│  · 抽题算法：_priority_sample / _balanced_sample_by_type        │
│  · 掌握度计算：_recalc_mastery_fields                         │
│  · 错题规则：add_wrong_record / add_correct_record             │
│  · 批量I/O：batch_update_wrong_and_stats / batch_add_answer_  │
│  · 缓存管理：_get_cached_stats / _data_version失效机制        │
├────────────────────────────────────────────────────────────────────┤
│                    数据访问层 (Data Access Layer)                  │
│  utils/data_access.py —— SQLite DAO（1580行，单例模式）        │
│  · 建表逻辑：_init_db（含动态ALTER TABLE补列）                │
```

## 2. 数据访问层设计（DAO）

### 2.1 单例模式

`data_access.py` 通过模块级全局变量 `_dao_instance` 实现单例，业务层通过 `_get_dao()` 获取实例，确保全进程共享同一数据库连接。

```python
def _get_dao():
    global _dao_instance
    if _dao_instance is None:
        _dao_instance = SQLiteDataAccess()
    return _dao_instance
```

### 2.2 建表与动态补列

`_init_db()` 在 DAO 首次初始化时执行：
1. 按顺序创建所有表（questions / answer_records / question_stats / wrong_questions / exam_records / mock_exam_records / study_records / drafts / config）
2. 对已有表执行 `PRAGMA table_info()` 检测缺失列，用 `ALTER TABLE ... ADD COLUMN` 动态补齐
3. 创建索引（questions.exam_type、question_stats.exam_type 等）

**注意**：部分表的 `exam_type` 列依赖运行时补列，属 P1 级别技术债。

### 2.3 事务保护

批量操作使用独立连接+事务，确保原子性：

```python
def batch_update_wrong_and_stats(self, exam_type, wrong_qids, correct_qids, stats_updates):
    with self._get_conn() as conn:
        cursor = conn.cursor()
        # 1. 更新 wrong_questions 表
        # 2. 更新 question_stats 表（批量）
        conn.commit()
```

### 2.4 per-rerun 缓存

`_rerun_cache_questions` 和 `_rerun_cache_stats` 为模块级字典，在本次 rerun 内缓存查询结果，避免同一次 rerun 中对同一数据多次查询。每次 rerun 开始时由 `invalidate_rerun_cache()` 清空。

## 3. 核心业务算法设计

### 3.1 优先级抽题算法

**目标**：让用户优先看到最薄弱的题目。

**四层排序**（关联系数计算后用 `_priority_sample` 执行）：

| 排序键 | 说明 |
|---------|------|
| `wrong_count - correct_count` 降序 | 答错多于答对的题优先 |
| 答错过(0) > 从未答过(1) > 答对过(2) | 副排序 |
| `wrong_count` 降序 | 同层级内高频错题优先 |
| 随机 | 最终平局打破 |

### 3.2 均衡采样算法

**目标**：确保超类下各子板块均匀出题，避免大板块垄断。

**算法步骤**（`_balanced_sample_by_type`）：
1. 计算基础配额：`base = total // n`
2. 前 `extra` 个类别多分1道（`extra = total % n`）
3. 各子板块内部按优先级排序后取前 N 道
4. 配额未用完时从剩余题目中按优先级补齐

### 3.3 掌握度计算算法

**目标**：基于历史答题记录，计算每道题的掌握度等级（0-5级）。

**输入**：该题所有历史答题记录（answer_records 表）

**计算步骤**（`_recalc_mastery_fields`）：
1. 统计 `correct_count`、`wrong_count`
2. 计算正确率 `accuracy = correct_count / (correct_count + wrong_count)`
3. 映射正确率到掌握度等级：

| 正确率范围 | 等级 | 说明 |
|-----------|------|------|
| < 20% | 0级 | 未掌握 |
| 20%-40% | 1级 | 薄弱 |
| 40%-60% | 2级 | 入门 |
| 60%-80% | 3级 | 良好 |
| 80%-95% | 4级 | 熟练 |
| ≥ 95% | 5级 | 精通 |

4. 计算置信度：答题次数越多置信度越高（`confidence = min(1.0, (correct_count + wrong_count) / 10)`）
5. 检测不稳定标记：
   - **消退型**：近期正确率明显低于远期 → `unstable = 1, retention_due = 计算值`
   - **波动型**：正确/答错交替出现 → `unstable = 1`

### 3.4 错题入出本规则

**入本条件**（满足以下所有条件）：
- `wrong_count >= correct_count`
- `wrong_count > 0` 或 `correct_count > 0`（至少答过一次）

**出本条件**（满足以下任一条件）：
- `correct_count > wrong_count`（答对次数严格大于答错次数）
- 用户手动点击"我已掌握本题"且 `correct_count > wrong_count`

## 4. 缓存与性能设计

### 4.1 三级缓存体系

| 缓存层级 | 存储位置 | 失效时机 | 用途 |
|----------|----------|---------|------|
| per-rerun缓存 | `data_access.py` 模块级字典 | 每次 rerun 开始（`invalidate_rerun_cache()`） | 避免同次 rerun 多次查询 DAO |
| session_state缓存 | `st.session_state._stats_cache` 等 | `_data_version` 变化时 | 避免跨 rerun 重复读取数据库 |
| 版本号失效 | `st.session_state._data_version` | 每次数据写入后 `+1` | 触发 session_state 缓存失效 |

### 4.2 批量I/O设计

**优化前**（v2.1及之前）：每题依次调用 `add_wrong_record` / `add_correct_record` / `add_answer_record`，每次调用执行一次数据库读写。

**优化后**（v2.2及之后）：
1. 提交时先收集所有操作数据（wrong_qids / correct_qids / stats_updates / answer_records）
2. 调用 `batch_update_wrong_and_stats()` 一次性更新错题库和答题统计（1次事务）
3. 调用 `batch_add_answer_records()` 一次性追加答题记录（1次事务）

**效果**：250题提交从 ~500+ 次 I/O 降至 ~4 次 I/O，性能提升近百倍。

### 4.3 首页统计缓存

`statistics.py` 中的 `_get_cached_stats()` 函数：
1. 检查缓存版本号是否等于 `_data_version`
2. 命中：直接返回缓存数据（0次 I/O）
3. 未命中：从数据库加载6类数据，存入缓存（6次 I/O）

## 5. 数据库设计（SQLite）

### 5.1 表关系图

```
questions (题目主表)
    ├── 1:N ──> answer_records (答题记录)
    ├── 1:1 ──> question_stats (答题统计)
```

|------|------|------|------|

| source_file | TEXT | NOT NULL | 来源docx文件名 |
| index | INTEGER | | 题目在源文件中的序号 |

| answer | TEXT | NOT NULL | 正确答案 |

| 字段 | 类型 | 约束 | 说明 |

## 6. 页面路由与状态机设计

### 6.1 页面路由

`app.py` 使用自定义侧边栏导航（隐藏 Streamlit 默认多页面导航），路由逻辑：

```python
menu_items = {
    "首页": "🏠",
    "专项训练": "🎯",
    "模拟考试": "📝",
    "巩固练习": "🔁",
    "错题本": "📕",
    "助记助学": "🧠",
    "配置管理": "⚙️",
}
```

选中后通过 `import` 动态加载对应页面模块，避免启动时加载全部页面。

### 6.2 各页面状态机

**专项训练（specialized.py）**：

```
idle ──► running ──► submitted
  │                      │
  │                      └──► idle (再做一次/返回)
  └──► idle (返回首页)
```

- `idle`：开始界面（选择板块/恢复草稿）
- `running`：答题进行中（可保存草稿）
- `submitted`：提交后成绩报告

**模拟考试（mock_exam.py）**：

```
idle ──► psychology ──► psychology_finished
                              │
                              └──► counseling ──► counseling_finished
                                                                 │
                                                                 └──► all_finished
```

- 两科独立计时、独立提交
- 支持草稿保存与恢复

**巩固练习（consolidation.py）**：

```
idle ──► running ──► submitted
```

- 与专项训练类似，但题目来源为"不稳固题目"

**错题本（wrongbook.py）**：

```
解析模式：idle（左侧列表 + 右侧详情）
做错题模式：idle ──► running ──► submitted
```

## 7. 草稿系统设计

### 7.1 草稿数据结构

存储于 `drafts` 表，`data` 字段为 JSON 字符串：

```json
{
  "draft_id": "spec_abc123",
  "draft_type": "spec",
  "exam_type": "心理学会咨询师四级",
  "category": "心理学导论",
  "mode": "specialized",
  "question_ids": ["xxx", "yyy", ...],
  "answers": {"xxx": "A", "yyy": ["A", "B"], ...},
  "submitted": false,
  "saved_at": "2026-06-28T19:00:00.000000"
}
```

### 7.2 草稿保存与恢复流程

**保存**：
1. 用户在答题过程中点击"保存草稿"
2. 收集当前 `question_ids`、`answers`、当前进度
3. 调用 `save_draft(draft_type, data)` 写入 `drafts` 表
4. 提示"草稿已保存"并返回开始界面

**恢复**：
1. 开始界面加载该 `draft_type` 的所有草稿
2. 用户点击"继续作答"
3. 从 `drafts` 表读取草稿数据
4. 恢复 `question_ids`、`answers`、当前进度
5. 进入 `running` 状态继续答题
