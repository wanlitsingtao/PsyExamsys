## 1. 系统架构设计

### 1.1 分层架构

系统采用四层分层架构：

```
┌────────────────────────────────────────────────────────────┐
│                    展示层 (Presentation)                    │
│  Streamlit Web界面（本地C/S模式）                          │
│  app.py ── 主控制器、路由分发（5个活跃页面）               │
│  pages/  ── specialized / mock_exam / wrongbook /          │
│             statistics / settings                          │
├────────────────────────────────────────────────────────────┤
│                    业务逻辑层 (Business Logic)               │
│  优先级抽题 / 均衡采样 / 答案判断 / 成绩计算 /             │
│  错题排序 / 倒计时管理 / 批量数据更新                     │
│  Session State 状态机                                      │
├────────────────────────────────────────────────────────────┤
│                    数据访问层 (Data Access)                  │
│  utils/parser.py       —— docx解析器                       │
│  utils/data_manager.py —— 数据CRUD + 去重 + 批量更新       │
├────────────────────────────────────────────────────────────┤
│                    数据存储层 (Storage)                     │
│  data/questions.json        （题库: 1878题）               │
│  data/wrong_questions.json  （错题库: 纯qid列表）          │
│  data/question_stats.json   （答题统计）                   │
│  data/config.json           （系统配置）                   │
│  data/mock_exam_records.json（模拟考试记录）               │
│  data/answer_records.json   （答题过程记录）               │
│  data/study_records.json    （训练会话记录）               │
│  exmbase/                   （原始docx源文件）              │
└────────────────────────────────────────────────────────────┘
```

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **单一职责** | 每个模块只负责一个功能域 |
| **数据驱动** | JSON文件作为唯一数据源，零数据库依赖 |
| **无状态+Session** | 业务逻辑无状态，交互状态由Streamlit Session State管理 |
| **本地优先** | 所有数据存储在本地文件系统 |
| **批量优先** | 写操作优先使用批量函数，减少JSON文件I/O次数 |

### 1.3 技术选型

| 技术 | 版本 | 选型理由 |
|------|------|---------|
| Python | 3.14 | 统一语言，python-docx原生支持 |
| Streamlit | 1.57 | 纯Python构建，内置Session State，无需前后端分离 |
| python-docx | 1.2 | 成熟的docx解析库 |
| JSON | - | 零配置、结构灵活、易于备份迁移 |
| hashlib(MD5) | 标准库 | 轻量级去重 |

### 2.3 题库解析器模块（utils/parser.py）

#### 2.3.1 解析流程

```
逐行扫描docx段落 →
匹配题号正则 ^(\d+)\.\s+...\((单选题|多选题|判断题|不定项选择题)\) →
提取题号、题目内容、题型 →
匹配选项行 ^[A-Z][：:]\s*... →
匹配"正确答案："行 →
匹配"答案解析："行 →
标准化处理（判断题→A/B、多选题排序去重） →
推断知识板块（CATEGORY_MAP） →
生成MD5哈希（取前12位为ID） →
输出完整题目字典
```

#### 2.3.2 正则模式

| 匹配目标 | 正则表达式 | 示例 |
|---------|-----------|------|
| 题号+题型 | `^(\d+)\.\s+(.+?)\s*\((单选题\|多选题\|判断题\|不定项选择题)\)` | `1. 会谈的核心作用（  ）。(单选题)` |
| 选项 | `^([A-Z])[：:]\s*(.*)` | `A：建立咨询关系` |
| 答案 | `^正确答案[：:]\s*(.+)` | `正确答案：C` |
| 解析 | `^答案解析[：:]\s*(.+)` | `答案解析：出处：P4...` |

#### 2.3.3 标准化规则

| 题型 | 处理规则 |
|------|---------|
| 判断题 | 答案"正确/对/√/true"→"A"，"错误/错/×/false"→"B"；自动生成选项{"A":"正确","B":"错误"} |
| 多选题 | 答案去空格、大写、去重排序，"A B D"→"ABD" |
| 单选题 | 答案去空格、大写，"c"→"C" |

#### 2.3.4 MD5去重哈希

```python
content = question_text + str(sorted(options.items())) + answer
md5 = hashlib.md5(content.encode("utf-8")).hexdigest()
id = md5[:12]
```

#### 2.4.2 核心工具函数

```python
def extract_questions(questions, dan_count=40, duo_count=30, pan_count=30):
    """按题型比例随机抽题，打乱顺序返回"""
    singles = [q for q in questions if q["type"]=="single"]
    multis  = [q for q in questions if q["type"]=="multi"]
    judges  = [q for q in questions if q["type"]=="judge"]
    selected = []
    selected += random.sample(singles, min(dan_count, len(singles)))
    selected += random.sample(multis,  min(duo_count, len(multis)))
    selected += random.sample(judges,  min(pan_count, len(judges)))
    random.shuffle(selected)
    return selected

def check_answer(question_type, user_answer, correct_answer):
    """判断答案是否正确"""
    if question_type in ("single", "judge"):
        return user_answer.strip().upper() == correct_answer.strip().upper()
    elif question_type in ("multi", "indefinite"):
        return set(user_answer.upper()) == set(correct_answer.upper())
```

### 3.2 错题库数据结构（v2.2 新格式）

```json

  "02631b85c794",
  "03ef6a1e3d3b"

```

**v2.2 重大变更**：从对象列表格式简化为**纯题号ID列表**。

| 维度 | 旧格式 (v2.1) | 新格式 (v2.2) |
|------|-------------|-------------|
| 数据结构 | `[{question_id, wrong_count, last_wrong_time, wrong_records}]` | `["qid1","qid2",...]` |
| wrong_count 来源 | 错题库自维护 | question_stats.json 的 wrong_count |
| 判断规则 | 以最后一次答题为准 | 基于累计统计 (wc vs cc) |
| 兼容性 | - | `_extract_qids_from_wrong_list()` 同时支持新旧格式 |

**错题判断规则（v2.2）**：

| 场景 | 规则 | 结果 |
|------|------|------|
| 答错，且 wc >= cc，且至少答过一次 | 入错题本 | qid 加入列表 |
| 答错，但 wc < cc | 不错题（历史答对较多） | 保持不变 |
| 答对，且 cc > wc | 出错题本 | qid 从列表移除 |
| 答对，但 wc >= cc | 仍为错题 | 保持在列表中 |
| wc=0, cc=0 | 从未答过 | 确保不加入错题本 |

### 5.1 优先级抽题算法（v2.2）

```python
def _priority_sample(questions, count):
    """
    时间复杂度: O(n log n)
    空间复杂度: O(n)
    
    三层排序优先级：
    1. 主排序值: (wrong_count - correct_count) 降序（差值越大越优先）
    2. 副排序值（层级）: 0=答错过 > 1=从未答过 > 2=答对过
    3. 同层级内: wrong_count 降序
    4. 最终平局: random 随机打破
    
    返回前count题
    """
```

## 7. 错误处理与异常机制

### 7.1 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| 题库为空 | 显示警告"题库为空，请先在配置管理中导入题库"，禁用操作按钮 |
| docx解析失败 | 返回error统计，不中断批量导入流程，其他文件正常解析 |
| 配置文件损坏 | 使用DEFAULT_CONFIG恢复，覆盖损坏文件 |
| JSON文件损坏 | 自动重建空数据结构（[]或{}），不影响应用启动 |
| 题库不足指定数量 | 全部抽取，不足部分跳过（不报错） |
| 倒计时耗尽 | 自动调用_finish_exam()提交，未答算错 |
| 考试中途异常关闭 | 数据不会丢失（已答答案存于Session State），但需重新开始考试 |
| 备份目录不存在 | 自动创建（ensure_dirs） |
| 文件编码异常 | 使用utf-8编码，errors='replace'处理 |
| 错题库格式兼容 | `_extract_qids_from_wrong_list()` 同时支持新旧格式 |

### 7.2 数据完整性保护

- 所有写操作使用 `with open + json.dump` 原子写入
- 重要操作（清空题库/错题）需要二次确认
- 每日首次启动自动备份数据文件
- 错题规则确保 wc=0,cc=0 的题目不会错误入本
