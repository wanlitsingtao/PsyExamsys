## 1. 系统架构设计

### 1.1 分层架构

系统采用四层分层架构：

```
┌────────────────────────────────────────────────────────────┐
│                    展示层 (Presentation)                    │
│  Streamlit Web界面（本地C/S模式）                          │
│  app.py ── 主控制器、路由分发（6个活跃页面）               │
│  pages/  ── statistics / specialized / mock_exam /        │
│             consolidation / wrongbook / settings           │
├────────────────────────────────────────────────────────────┤
│                    业务逻辑层 (Business Logic)               │
│  优先级抽题 / 均衡采样 / 答案判断 / 成绩计算 /             │
│  错题排序 / 倒计时管理 / 批量数据更新 /                   │
│  session_state 缓存 + _data_version 失效机制               │
├────────────────────────────────────────────────────────────┤
│                    数据访问层 (Data Access)                  │
│  utils/parser.py       —— docx解析器                       │
│  utils/data_manager.py —— 数据CRUD + 去重 + 批量更新       │
├────────────────────────────────────────────────────────────┤
│                    数据存储层 (Storage)                     │
│  data/questions.json        （题库: 1878题）               │
│  data/wrong_questions.json  （错题库: 纯qid列表）          │
│  data/question_stats.json   （答题统计）                   │
│  data/config.json           （系统配置）                   │
│  data/mock_exam_records.json（模拟考试记录）               │
│  data/answer_records.json   （答题过程记录）               │
│  data/study_records.json    （训练会话记录）               │
│  exmbase/                   （原始docx源文件）              │
└────────────────────────────────────────────────────────────┘
```

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **单一职责** | 每个模块只负责一个功能域 |
| **数据驱动** | JSON文件作为唯一数据源，零数据库依赖 |
| **无状态+Session** | 业务逻辑无状态，交互状态由Streamlit Session State管理 |
| **本地优先** | 所有数据存储在本地文件系统 |
| **批量优先** | 写操作优先使用批量函数，减少JSON文件I/O次数 |
| **缓存+版本失效** | 高频率读操作使用 session_state 缓存，通过 _data_version 控制失效（v2.3） |

### 1.3 技术选型

| 技术 | 版本 | 选型理由 |
|------|------|---------|
| Python | 3.14 | 统一语言，python-docx原生支持 |
| Streamlit | 1.57 | 纯Python构建，内置Session State，无需前后端分离 |
| python-docx | 1.2 | 成熟的docx解析库 |
| JSON | - | 零配置、结构灵活、易于备份迁移 |
| hashlib(MD5) | 标准库 | 轻量级去重 |

### 2.3 题库解析器模块（utils/parser.py）

#### 2.3.1 解析流程

```
逐行扫描docx段落 →
匹配题号正则 ^(\d+)\.\s+...\((单选题|多选题|判断题|不定项选择题)\) →
提取题号、题目内容、题型 →
匹配选项行 ^[A-Z][：:]\s*... →
匹配"正确答案："行 →
匹配"答案解析："行 →
标准化处理（判断题→A/B、多选题排序去重） →
推断知识板块（CATEGORY_MAP） →
生成MD5哈希（取前12位为ID） →
输出完整题目字典
```

#### 2.3.2 标准化规则

| 题型 | 处理规则 |
|------|---------|
| 判断题 | 答案"正确/对/√/true"→"A"，"错误/错/×/false"→"B"；自动生成选项{"A":"正确","B":"错误"} |
| 多选题 | 答案去空格、大写、去重排序，"A B D"→"ABD" |
| 单选题 | 答案去空格、大写，"c"→"C" |

#### 2.3.3 MD5去重哈希

```python
content = question_text + str(sorted(options.items())) + answer
md5 = hashlib.md5(content.encode("utf-8")).hexdigest()
id = md5[:12]
```

## 7. 性能优化设计

### 7.1 缓存+版本失效机制（v2.3 核心优化）

**问题**：每次页面导航触发大量重复 JSON 文件 I/O，首页每次渲染 ~12 次读盘，导致切换明显延迟。

**方案**：`session_state` 缓存 + `_data_version` 失效计数器。

```
首次进入首页 → 读盘 6 次 → 写入 session_state 缓存
切换页面（无数据变更）→ 缓存命中 → 0 次读盘
提交答案 → _data_version +1 → 下次首页 → 缓存失效 → 重新加载
```

**修改文件及优化点**：

| 文件 | 优化内容 | 效果 |
|------|---------|------|
| app.py | 缓存 `get_wrong_stats` + `get_available_exam_types` | 侧边栏 4次→0次 |
| statistics.py | `_get_cached_stats()` 包裹 6 个 load | 首页 12次→首次6次/后续0次 |
| consolidation.py | `consol_stats_cache` 替代 `get_question_stats()` | 每题渲染 1次→0次 |
| wrongbook.py | `wb_stats_cache` 替代 `get_question_stats()` | 每题渲染 1次→0次 |
| specialized.py | 提交后 `_data_version += 1` | 触发缓存刷新 |
| mock_exam.py | 提交后 `_data_version += 1` | 触发缓存刷新 |
| settings.py | 导入/清空后 `_data_version += 1`（3处） | 触发缓存刷新 |

### 7.2 批量 I/O 操作

所有提交操作使用 `batch_update_wrong_and_stats()` 和 `batch_add_answer_records()`，将逐题数百次 I/O 压缩为 4 次以下。

## 8. 错误处理与异常机制

### 8.1 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| 题库为空 | 显示警告"题库为空，请先在配置管理中导入题库"，禁用操作按钮 |
| docx解析失败 | 返回error统计，不中断批量导入流程 |
| 配置文件损坏 | 使用DEFAULT_CONFIG恢复 |
| JSON文件损坏 | 自动重建空数据结构，不影响启动 |
| 题库不足指定数量 | 全部抽取，不足跳过 |
| 倒计时耗尽 | 自动调用_finish_exam()提交，未答算错 |
| 错题库格式兼容 | `_extract_qids_from_wrong_list()` 同时支持新旧格式 |
| exam_type 冗余过滤 | v2.3 已修复：`get_mastery_distribution()` 不再内部过滤 |

### 8.2 数据完整性保护

- 所有写操作使用 `with open + json.dump` 原子写入
- 重要操作需二次确认
- 每日首次启动自动备份
- 错题规则确保 wc=0,cc=0 的题目不会错误入本
