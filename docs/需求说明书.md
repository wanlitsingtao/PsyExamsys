# 第一部分：需求说明书

## 1. 项目概述

### 1.1 项目背景
题库文件位于 `E:\LingMa\exmsys\exmbase` 目录下，包含11个docx格式的考题文件，覆盖心理咨询师考试的基础理论和咨询实务两大模块，含单选题、多选题、判断题、不定项选择题四种题型，总计1878道题目。需要基于这些题目构建一个功能完整的背题系统。

### 1.2 项目目标
开发一套包含**首页（数据统计）、专项训练、模拟考试、巩固练习、错题本、助记助学、配置管理**七大模块的心理咨询师考试辅助学习系统，帮助用户高效备考。

### 1.3 用户角色

| 角色 | 标识 | 获得方式 | 权限 |
|------|------|---------|------|
| **普通用户（考生）** | `role='user'` | 首次访问按设备指纹自动创建，零门槛 | 全部学习功能；**只能导入/清空自己的私人题库**（不影响公共题库） |
| **管理员** | `role='admin'` | 内置账号 `admin` / `admin`（`user_id` 由 `md5(b"exmsys_admin_account")[:12]` 派生，与设备用户不冲突） | 学习功能 + 公共题库维护（导入/清空，带二次确认）+ 用户列表查看 + 系统参数配置 |

**权限边界（v2.5 明确）**

- 用户导入题库、清空题库，**只作用于自己的私人题库**（`owner_id = 自己的 user_id`）；
- **公共题库只有管理员能改**（`owner_id = '__public__'`）；普通用户界面不出现"导入公共题库"选项；
- 管理员清空公共题库时，用户侧的统计/错题/答题记录**一律保留**（题目 ID 不变，仅内容消失），
  界面会明确提示这一点；
- 管理员账号初次使用提示修改默认密码；密码以 SHA-256 哈希存于 `users.password_hash`。

> **默认题库的选择**：可用题库类型按名称排序后取第一个作为新会话默认
> （当前为 `心理协会咨询师初级` 444 题；另有 `心理学会咨询师三级` 2559 题、`心理学会咨询师四级` 2115 题）。

### 2.2 首页（数据统计）模块

#### 2.2.1 功能描述
系统默认首页，采用五维 Tab 面板展示用户学习全貌。Tab 顺序：错题统计 → 知识掌握情况分析 → 答题统计 → 考试记录 → 相关性分析。所有数据采用 session_state 缓存机制，仅在数据版本变化时重新加载，确保页面秒开。

#### 2.2.2 五个统计维度

| Tab标签 | 内容 |
|---------|------|
| 📕 错题统计 | 错题总数、最高答错次数（当前题库所有答过的题的历史最大答错次数，不限是否仍在错题本内）、错题占比、知识板块错题分布（含错题比率：错题数/板块总题数×100%）、高频错题TOP 20（当前题库所有答过的题按历史累计答错次数降序，含已移出错题本的题） |
| 🧠 知识掌握情况分析 | 已学率、掌握/不稳定/待复习/遗忘预警/未学 分布饼图、各知识板块掌握度分布、掌握度等级明细列表 |
| 📝 答题统计 | 总答题次数、正确率、各模式统计（专项/模拟/错题本/巩固）、各板块答题统计、最近50条答题记录 |
| 📋 考试记录 | 模拟考试记录（按会话分组显示两科成绩、正确率、用时） |
| 📊 相关性分析 | 题目答题相关性分析（引入 pages/correlation.py） |

#### 2.3.3 交互逻辑

1. **开始训练**：选择综合训练或指定知识板块，系统按优先级抽题算法抽取题目（默认30单选+20多选+10判断），按单选→多选→判断顺序排列
2. **答题过程**：
   - 可任意切换题目（上一题/下一题/答题卡点击跳转）
   - 答题卡使用 Streamlit 原生 `st.button` 网格（支持颜色标记和导航）
   - 随时点击"查看答案"展开/收起正确答案和解析
   - 显示该题历史答题统计和上次答题结果标记
   - 支持"保存草稿"功能，中途退出后可恢复
3. **提交答案**：
   - 点击"提交全部答案"，使用批量操作一次性评分并更新数据
   - 多选题和不定项选择题：必须完全匹配才得分（漏选、多选均不得分）
   - 未答题目按错误处理
4. **成绩计算**：
   - 单选题每题1分，多选题每题1.5分，判断题每题0.5分
   - 满分为 30×1.0 + 20×1.5 + 10×0.5 = 65分
5. **结果记录**（批量写入，减少I/O）：
   - 答错题自动加入错题库（遵循错题统计规则）
   - 答对题从错题库移除（如符合移除条件）
   - 更新每题累计答对/答错次数统计
   - 追加答题过程记录
6. **草稿恢复**：
   - 用户在答题过程中可保存草稿
   - 开始界面显示未完成训练列表
   - 点击"继续作答"恢复草稿，继续答题

### 2.5 巩固练习模块

#### 2.5.1 功能描述
独立模块（与错题本并列），专注于**掌握不牢靠**和**遗忘预警**的题目。从知识掌握情况分析中筛选出不稳固（掌握不牢 + 遗忘预警）的题目，按优先级排序抽取最多60题进行集中训练。采用统一提交模式，提交后展示正确题目回顾和错题复盘双重反馈。支持草稿保存与恢复。

#### 2.5.2 出题优先级（四层排序）

| 优先级 | 条件 | 说明 |
|--------|------|------|
| tier0 | 处于"消退型"列表 | 最优先出题（掌握度严重退化） |
| tier1 | 处于"遗忘预警"列表 | 次优先出题 |
| tier2 | 处于"波动型"列表 | 补充出题 |
| tier3 | 标记为"不确定"的题目 | 补充出题 |

同层级内按 `wrong_count - correct_count` 降序排列。

#### 2.5.3 交互逻辑

1. **开始练习**：选择巩固练习 → 系统自动筛选不稳固题目 → 按优先级抽取最多60题
2. **答题过程**：与专项训练一致的统一提交模式，答题卡导航，支持草稿保存
3. **提交成绩**：批量操作更新错题本和答题统计（含 `_data_version += 1` 触发首页缓存刷新）
4. **成绩报告**：
   - ✅ **正确题目回顾**：每道正确题可展开查看题目、选项和解析
   - ❌ **错题复盘**：每道错题展开显示题目、选项（绿色✅=正确答案、红色❌=用户错选、⬜=漏选）、用户答案与正确答案对比、解析
   - 分题型统计正确率
5. **数据更新**：成绩纳入错题本和答题统计，与其他模块联动

### 2.6 错题本模块

#### 2.6.1 功能描述
提供**错题解析**和**做错题**两种模式。错题解析模式以左右布局展示错题列表和详细解析；做错题模式从错题库中提取最多50道题进行统一提交训练。错题库以纯题号列表（qid数组）形式存储在 SQLite 数据库中，所有统计数据从 question_stats 表读取。

#### 2.6.2 错题判断规则

**核心规则**（v2.2）：
- 错题判定依据 `question_stats` 表中的累计统计数据（`correct_count`/`wrong_count`），而非单独维护的 `wrong_count` 字段
- 入错题本条件：`wrong_count >= correct_count` **且** 至少答过一次（`wrong_count > 0` 或 `correct_count > 0`）
- 出错题本条件：`correct_count > wrong_count`（即答对次数严格大于答错次数）
- 从未答过的题目（`wc=0, cc=0`）不会进入错题本

#### 2.6.3 交互逻辑

1. **错题解析模式**：左侧按易错程度排序的题目列表，点击后在右侧显示完整题目、选项、正确答案和解析
2. **做错题模式**：从错题库按优先级排序抽取最多50题，统一提交答题模式
3. **我已掌握本题**：手动将某题从错题本移除（仅当 `correct_count > wrong_count` 时生效）
4. **清空错题本**：二次确认后清空所有错题记录
5. **错题统计**：所有统计数据从 `question_stats` 表读取（易错程度按 `wrong_count - correct_count` 降序排列）

### 2.7 助记助学模块（v2.3 新增）

#### 2.7.1 功能描述
将题库中涉及**数字答案**、**人名答案**和**量表维度**的题目整理为速查表格，方便考前冲刺记忆。包含四个 Tab：数字相关、量表相关、人名相关、不确定题目。

#### 2.7.2 四个 Tab 内容

| Tab标签 | 内容 |
|---------|------|
| 🔢 数字相关 | 按内容类型分类：月龄（升序）、岁数（升序）、病程/时长（升序）、量表分数（降序）、量表条目（降序）、其他数字题 |
| 📊 量表相关 | 量表维度、量表分数（划界分/常模分/总分阈值）、量表条目数 |
| 👤 人名相关 | 题干含人物关键词、选项为2-4字纯中文的人名题，按知识板块分组 |
| ❓ 不确定题目 | 用户在答题过程中标记为"不确定"的题目，支持展开查看详情和移除标记 |

#### 2.7.3 交互逻辑

1. **数字相关 Tab**：
   - 按月龄、岁数、病程时长、量表分数、量表条目等分类展示
   - 每类题目按数值排序（月龄/岁数升序，分数降序）
   - 支持搜索过滤

#### 2.8.1 功能描述

| Tab | 普通用户 | 管理员 |
|-----|---------|--------|

| 用户列表 | ❌ 不可见 | ✅ 可见 |

#### 2.8.2 题库管理（按角色分区）

**普通用户**
- 只显示一个作用域选项：**导入到我的题库**
- 统计区显示：我的题库题数、公共题库题数、可见总题数
- 清空按钮只清空**自己的**私人题库，公共题库不受影响

**管理员**
- 作用域可选：**我的题库** / **公共题库**
- 选「公共题库」时必须**勾选确认**（"我已确认这是对全体用户生效的公共题库"）才允许导入，防止误操作
- 选「公共题库」清空时显示强警告，并明确说明：
  「用户的统计/错题/答题记录会保留（题目 ID 不变），仅题目内容从公共题库移除」

**通用能力**
- 显示已导入题库文件列表及统计
- 支持多种题库类型（`exam_type`）切换
- 批量导入 `exmbase` 目录所有 docx，也支持上传 docx 文件
- 导入采用 **upsert 配对**（取代旧的"删表重建"）：
  1. 内容指纹（题干+选项+答案，两侧现算）完全一致 → 视为同一题，**复用原 ID**；
  2. `(source_file, index_num, type)` 一致 → 视为同一题；
  3. 同一源文件内题干文本相似度 ≥ 0.60 → 视为同一题（题干被改过的情形）；
  4. 都配不上 → 生成新 ID 插入。
  - 导入模式：`append`（只增改，默认，安全）/ `replace`（视为该作用域完整题库，删除未匹配到的旧题）
  - 导入报告：新增 / 更新 / 未变 / 删除 / 跳过的条数与明细
- **ID 稳定的意义**：管理员修正公共题库里的错题后，用户端看到的是修正后的内容，
  而用户的错题本、掌握度、答题历史全部**零断链**（这正是"用户题库与初始题库通过 ID 关联"的落地方式）
- 题号不可靠时的处理：`(source_file, index_num)` 在现题库中并不唯一
  （曾有文件 220 题全部 `index_num=0`），因此它只作为二级信号，且模糊配对设有
  20 万次比较预算，超预算则跳过模糊配对、宁可多生成新题也不卡死导入

#### 2.8.3 系统设置
- 专项训练每轮题量配置（默认总数 60）
- 模拟考试参数配置
- 错题本提取数量（默认 50，可调 10~100）

#### 2.8.4 用户列表（仅管理员）

- 只读展示（用户管理走数据库运维，应用内不提供删改入口）

## 3. 非功能性需求

### 3.1 性能要求

### 3.3 易用性要求
- 所有交互操作有明确反馈提示（st.success/error/warning/info）
- 重要操作（提交试卷、清空错题/题库）有二次确认

- 答题卡按钮字号 CSS 缩小至 10px，确保三位数题号不换行
- 全局基础字号 18px

### 3.4 数据持久化
- 所有数据以 SQLite 数据库存储于 **`data/exmsys.db`（单库）**

## 4. 数据存储设计（SQLite 单库多租户）

> **v2.5 结构变更**：题库与用户数据表都增加了归属列，实现"一个库装所有人"。

### 4.0 归属列约定

| 列 | 取值 | 含义 |
|----|------|------|
| `questions.owner_id` / `case_studies.owner_id` | `'__public__'` | 公共题库（管理员维护，全体可见） |
| 同上 | `<user_id>` | 该用户的私人题库（仅自己可见） |
| 各用户数据表的 `user_id` | `<user_id>` | 数据归属；查询一律带此条件 |

**为什么公共 owner 用哨兵值 `'__public__'` 而不是 NULL**：
SQLite 中 NULL 互不相等，`UNIQUE(owner_id, md5)` 会因此失效（公共题库去重坏掉）。

**唯一索引**：`uniq_questions_owner_md5(owner_id, md5)` —— 内容去重限定在各自作用域内。

### 4.1 题库数据表（questions）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT (PK) | 题目唯一ID（12位）。**一经分配永不变更** |
| owner_id | TEXT NOT NULL | `'__public__'` 或 `<user_id>`（默认 `'__public__'`） |
| source_file | TEXT | 来源docx文件名 |
| index_num | INTEGER | 题目在源文件中的序号 |
| type | TEXT | 题型（single/multi/judge/indefinite/案例题） |
| question | TEXT | 题目文本 |
| options | TEXT (JSON) | 选项字典（JSON字符串存储） |
| answer | TEXT | 正确答案 |
| explanation | TEXT | 解析内容 |
| md5 | TEXT | 内容指纹（历史遗留：部分值与内容不一致，配对已改为两侧现算） |
| category | TEXT | 知识板块名称 |
| exam_type | TEXT | 题库类型（如"心理学会咨询师四级"） |
| case_study_id | TEXT | 案例题背景ID（案例题专用） |
| is_case_background | INTEGER | 是否为案例背景题 |

> **ID 生成规则**：`md5(f"{owner_id}|{题干}{排序后选项}{答案}")[:12]`。
> 把 owner 纳入哈希，避免"用户导入的题"与"公共题库同一道题"ID 撞车。
> 撞车兜底：若生成的 ID 已存在，则再加盐重算，保证不覆盖既有题。

### 4.2 错题库数据表（wrong_questions）

| 字段 | 类型 | 说明 |
|------|------|------|
| question_id | TEXT | 题目ID（对应 questions.id） |
| user_id | TEXT | 数据归属用户 |
| exam_type | TEXT | 题库类型 |
| **PK** | | **(question_id, user_id) 复合主键** |

### 4.3 题目答题统计数据表（question_stats）

| 字段 | 类型 | 说明 |
|------|------|------|
| question_id | TEXT | 题目ID（对应 questions.id） |
| user_id | TEXT | 数据归属用户 |
| exam_type | TEXT | 题库类型 |
| correct_count | INTEGER | 累计答对次数 |
| wrong_count | INTEGER | 累计答错次数 |
| last_answer_time | TEXT | 最后一次答题时间（ISO格式） |
| last_correct | INTEGER (0/1) | 最后一次答题是否正确 |
| mastery_level | INTEGER | 掌握度等级（0-5） |
| confidence | REAL | 掌握度置信度（0.0-1.0） |
| self_uncertainty | REAL | 自我不确定度 |
| unstable | INTEGER (0/1) | 是否不稳定（消退型/波动型） |
| first_answer_time | TEXT | 首次答题时间 |
| **PK** | | **(question_id, user_id) 复合主键** |

### 4.4 其他数据表

| 表名 | 归属列 | 说明 |
|------|--------|------|
| case_studies | owner_id | 案例背景（与 questions 同套分层规则） |
| answer_records | user_id | 答题过程全量记录（每次答题的题目、用户答案、结果） |
| exam_records | user_id | 考试记录（含专项训练、巩固练习、错题练习记录） |
| mock_exam_records | user_id | 模拟考试记录（按会话分组，含两科成绩） |
| study_records | user_id | 训练会话历史记录（PK = session_id） |
| drafts | user_id | 草稿保存（**PK = `{user_id}|{prefix}|{draft_id}`**，防不同用户同名草稿互相覆盖） |
| app_config | — | 全局配置（如题库数据版本号 `_questions_data_version`） |
| user_config | user_id | 每用户配置（PK = `(user_id, key)`） |
| users | — | 身份：user_id、username(UNIQUE)、password_hash、role、display_name、created_at、last_login |
| user_devices | — | 设备绑定：device_fp(PK)、user_id、first_seen、last_seen |

### 4.5 用户身份与 user_id 派生（兼容性契约）

```
设备指纹 fingerprint = md5(user_agent)[:32]
user_id             = md5("exmsys_device_" + fingerprint)[:12]
管理员 user_id       = md5(b"exmsys_admin_account")[:12]
密码存储             = sha256(password)
```

**该派生算法在改造前后**完全一致** —— 老用户迁移后 user_id 不变，
其原有统计、错题、答题记录全部正确接续，会话与学习进度无缝延续。

## 4. 核心模块设计

### 4.1 docx题库解析器 (parser.py)

解析规则（逐行扫描docx段落）：
1. 匹配 `^(\d+)\.\s` 开头 → 题目行
2. 题目行中检测 `(单选题|多选题|判断题|不定项选择题)` → 确定题型
3. 后续段落匹配 `^[A-Z][：:]` → 选项
4. 匹配 `正确答案：` → 答案
5. 匹配 `答案解析：` → 解析
6. **只计算内容指纹 `md5`**（`md5(题目 + str(sorted(选项.items())) + 答案)`），
   **不再生成题目 ID** —— ID 由数据访问层按 `owner_id` 作用域统一分配（见 4.2），
   这样才能保证"用户私题"与"公共题"不撞 ID
7. 案例题预扫描：`_detect_case_ranges()` 扫描案例题题号范围
8. 批量解析：`batch_parse()` 递归扫描子目录

### 4.2 数据访问层 (data_access.py)

**设计要点**：
- **单库多租户**：`SQLiteDataAccess(db_path=None, user_id=None)`，全系统一个库；
  `user_id` 是"当前用户上下文"，由 `data_manager.set_current_user()` 每帧幂等校正
  （模块级全局变量会被其他 Streamlit session 覆盖，这是必须每帧校正的原因）
- **单例模式**：`get_data_access(db_path, user_id)` 返回进程内唯一实例；`reset_data_access()` 丢弃
- **连接分两级**：`_get_conn()`（带 WAL/PRAGMA，用于读写）；
  `_get_light_conn()`（不带 PRAGMA，用于"每帧都要看一眼"的小查询——
  WAL 需取写锁，实测 259ms/次，是当时勾选答案卡顿的头号元凶）
- **事务保护**：批量操作单事务，异常回滚

### 4.6 答案判断逻辑

```python
def check_answer(question_type, user_answer, correct_answer):
    if question_type in ("single", "judge"):
        return user_answer.strip().upper() == correct_answer.strip().upper()
    elif question_type in ("multi", "indefinite"):
        user_set = set(user_answer.strip().upper().replace(" ", ""))
        correct_set = set(correct_answer.strip().upper().replace(" ", ""))
        return user_set == correct_set  # 完全匹配才得分
```

### 4.7 缓存失效机制（v2.3 新增）

```python
# 全局版本号，每次数据写入后递增
st.session_state._data_version = 0  # 初始化

# 写入操作后触发缓存失效
st.session_state._data_version += 1  # 递增

# 读取操作检查缓存
cache = st.session_state.get("_stats_cache", {})
if cache.get("_version") == st.session_state._data_version:
    return cache["data"]  # 命中缓存，0次I/O
else:
    data = load_from_disk()  # 未命中，重新加载
    st.session_state._stats_cache = {"_version": ..., "data": data}
```
